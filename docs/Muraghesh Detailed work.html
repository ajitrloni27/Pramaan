0 · Read this first — why your seat is load-bearing

The jury will ask two fatal questions: “How do you know it isn’t hallucinating?” and “Is this just a mail-merge script, or is it actually an agent?” The answers to both live entirely in your code:

  • The hallucination defense is Step 03 (COMPARE). It must be pure arithmetic over cited numbers. If you let an LLM anywhere near the subtraction, the product is a toy.
  • The agentic proof is Step 05 (ACT) and the Mock Gateway. An agent mutates external state. If the hold doesn't actually change state (even in a mock), it's just generating text.
  • The merge defense is the Schema Freeze at P1 10:30. If the contracts drift, Vrajesh’s UI breaks silently, and the sprint burns.

You are not “the backend guy.” You are the architect of the product's integrity. You own the HOW, and you are expected to push back on Vrajesh when the technical reality demands it.

11 · ⚠ The Non-Negotiables — your technical hills to die on

  • NEVER put a model in the compare path (step 03). The verdict is arithmetic over cited numbers. If anyone suggests “let the LLM decide the gap” — the answer is no.
  • NEVER weaken the two-tier hold (placed vs staged) for speed. A misread must at worst stage a hold or place a 72h hold that self-heals. Permanent consequences need the tap.
  • NEVER change a schema after P1 without a 2-min V–M sync. If drift is found late, the UI bends to the engine, never the reverse.
  • NEVER copy the pipeline for the lease. Lease = rulebook swap through the SAME trunk. Copy-pasting the engine is amputating the tree (rule #10).
  • NEVER let anyone else merge into services/brain — and a PR touching packages/contracts needs you AND Vrajesh.
  • NEVER crash on a step error. Append an “error” audit event, mark affected cards “unverified”, return a partial RunResponse.
  • NEVER put timestamps in the seeded payload. Byte-identical or the demo gamble returns.
  • NEVER inline a type. If the app or the brain wants a shape, it lives in packages/contracts.
