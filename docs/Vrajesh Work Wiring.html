⚠ CRITICAL — NEVER DO THIS

  • NEVER let the screen recompute gaps, decide hold status, or rewrite the draft. It renders RunResponse VERBATIM. The engine is authoritative — blurring that line is how verdicts quietly stop being true.
  • NEVER change a schema after P1 without a 2-min V–M sync — and if drift is found late, the UI bends to the engine. UI is cheaper to bend than verdict logic.
  • NEVER let a live OCR / LLM / network call into the 90 seconds. The demo is a rehearsed script on pre-seeded data (rule #6). Live calls happen in the build, never on stage.
  • NEVER find-and-replace across the UI when the engine merges. One dataSource, one env var (rule #2). If you’re editing ten files to flip a mode, the switch was built wrong — fix the switch.
  • NEVER add features in P9. Fix only what Ajit logs, then re-rehearse. A flawless demo of 80% beats 100% that glitches (rule #7).
  • NEVER demo an unsourced number. Citation gate — Manas signs off every rule, on-screen number, and slide stat. The team waits 10 minutes for a correct citation rather than demo a wrong number (rule #5).
  • NEVER pull an all-nighter. Sleep both nights, all four. The person who pulls the all-nighter writes the bug that breaks the 11 AM demo (rule #8).
  • NEVER copy the engine for the lease — lease = rulebook swap on the SAME screen. Copy-pasting is amputating the tree (rule #10).
  • NEVER let more than one voice answer a question. The owner answers; others stay quiet unless tagged. Four people talking = a team that didn’t rehearse (rule #9).
